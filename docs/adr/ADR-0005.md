# ADR-0005: Boson algebra layer

## Context
In bosonization, we require a space to represent bosonic operators satisfying the Canonical Commutation Relations (CCR), $[a_m, a_{m'}^\dagger] = \delta_{mm'}$. A well-known mathematical fact is that there is no finite-dimensional representation of $[A, B] = 1$ in characteristic zero (due to the trace argument, where $\operatorname{Tr}(AB - BA) = 0 \neq \operatorname{Tr}(1)$). Consequently, we cannot represent bosonic CCR exactly on finite matrices. We need an exact, rigorous algebraic framework that circumvents functional analysis and domain issues of unbounded operators in infinite-dimensional Hilbert spaces.

## Options
1. **Bounded operators on Hilbert spaces**: Heavy functional analysis, $C^*$-algebras, and spectral theory.
2. **Formal power series**: Abstract rings of formal series.
3. **Algebraic polynomial representation**: Using multivariate polynomials where creation/annihilation act via multiplication and formal derivatives.

## Decision
We will use an **umbral polynomial Fock representation**. The carrier space will be `MvPolynomial (BosonIdx Q) ℂ`. The creation operators are defined as multiplication by variables: $a^\dagger_m := X_m \cdot$. The annihilation operators are defined as formal partial derivatives: $a_m := \partial_m$ (`MvPolynomial.pderiv`). Unnormalized operators are $J^\dagger_m = X_m$ and $J_m = m \partial_m$. Automorphisms of this algebra (like the Bogoliubov transformation) will be handled abstractly using `RingQuot (FreeAlgebra …)`.

## Attacks
1. **Polynomials lack native inner products:** Unlike matrices, `MvPolynomial` makes defining true Hilbert space inner products and adjoints difficult.
   *Response:* We do not need full Hilbert space geometry. We only require algebraic properties and expectation values, which we obtain using the vacuum functional $\omega_0$ via `MvPolynomial.constantCoeff`.
2. **Abstract automorphisms are hard to compute with:** `RingQuot (FreeAlgebra)` might be difficult to evaluate concretely in proofs.
   *Response:* We only use `FreeAlgebra` for formulating the Bogoliubov transformation as an `AlgEquiv` to rigorously prove the diagonalization of the Hamiltonian, which is purely algebraic.
3. **What about unbounded operators?** Doesn't this ignore standard quantum mechanics?
   *Response:* Yes, intentionally. By operating in an algebraic quantum field theory (AQFT) setup, we bypass analysis entirely, eliminating domain issues in Core while keeping exact identities.

## Rollback
If multivariate polynomials prove too computationally heavy for specific proofs or if degree constraints are problematic, we can pivot to `PowerSeries`, treating expressions strictly as formal generating functions. However, `MvPolynomial` is strongly preferred for finite degrees and precise degree operators.

## Consequences for Lean
*   We will heavily utilize `MvPolynomial`, `MvPolynomial.pderiv`, `MvPolynomial.constantCoeff`, and abstract structures like `FreeAlgebra`, `RingQuot`, and `AlgEquiv`.
*   The exact CCR $[a_m, a_{m'}^\dagger] = \delta_{mm'}$ will be `Module.End` identities.
*   **Mathlib audit needed:** Ensure robust lemmas exist for `MvPolynomial`, `pderiv`, `FreeAlgebra`, and `RingQuot`.
