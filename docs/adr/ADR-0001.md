# ADR-0001: Fock-space representation

## Context
In our lattice-regularized AQFT, we need a concrete realization of the Fermionic Fock space for our modes (representing R and L chiralities, with $L$ modes each). We must represent creation and annihilation operators $c_i, c_i^\dagger$ satisfying the Canonical Anticommutation Relations (CAR): exact anticommutators $\{c_i, c_j^\dagger\} = \delta_{ij}$ and $\{c_i, c_j\} = 0$. Choosing the right representation is crucial because this foundational layer affects the performance and provability of all subsequent thermodynamic and algebraic properties in Lean.

## Options
1. **Abstract `CliffordAlgebra`**: Use Lean's universal Clifford algebra and define the modules abstractly.
2. **Jordan-Wigner matrices**: Tensor products of $2 \times 2$ matrices using `Matrix.kronecker`.
3. **Concrete Occupation Basis**: Implement a concrete basis mapping using `Finset (Mode L) → ℂ` with explicit parity sign factors.

## Decision
We will define an abstract interface `CARRep (ι) (V)` specifying operators `c, cdag : ι → Module.End ℂ V` that satisfy the CAR. We will then provide a concrete instance of this interface on `Fock ι := Finset ι → ℂ` (with `[LinearOrder ι]`), mapping a subset of occupied modes to its amplitude. The anticommuting sign logic will be explicitly handled by the factor $(-1)^{\#\{k \in S : k < i\}}$. The index type will be `ι = Chirality × Mode L`. We will prove that `Module.finrank = 2^card ι`.

## Attacks
1. **Matrix approach is computationally simpler:** For small models, matrix multiplication is native.
   *Response:* The matrix dimensions grow as $2^{2L}$, making symbolic manipulation of `Matrix.kronecker` exponentially complex and cumbersome to formalize generically in Lean. The occupation basis is more mathematically direct.
2. **Sign logic is error-prone:** Defining signs as $(-1)^{\#\{k \in S : k < i\}}$ invites off-by-one errors and complex combinatorial proofs.
   *Response:* By isolating the exact representation behind the `CARRep` interface, we only have to verify the sign logic once. The rest of the library relies solely on the abstract interface.
3. **`Module.End ℂ V` lacks built-in adjoints:** Standard linear maps don't natively enforce $C^*$ properties like adjoints.
   *Response:* We will define an explicit inner product on `Finset ι → ℂ` (the standard $\ell^2$ dot product) and formally prove that `cdag i` is the true Hilbert space adjoint of `c i`, satisfying `cdag i = (c i)†`.

## Rollback
If proving CAR on the concrete `Finset ι → ℂ` representation becomes too complex due to combinatorial sign manipulation, we can pivot to constructing it via `CliffordAlgebra` and proving CAR from its universal property, or use an inductive tensor-product approach. The `CARRep` interface ensures that consumer code remains completely unaffected by this change.

## Consequences for Lean
*   We heavily rely on types like `Finset ι → ℂ` and `Module.End ℂ V`.
*   We need `StarSubalgebra` and explicit `Equiv` for dimensions.
*   **Mathlib audit needed:** `CliffordAlgebra`, `ExteriorAlgebra`, `Matrix.kronecker`, `Finset.filter`, `Module.finrank`, and standard inner product structures.
